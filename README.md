# Cedric Richter’s academic website

A Markdown-based Jekyll site for GitHub Pages. The shared profile and navigation
live in `_layouts/default.html`; styling lives in `assets/css/academic.css`.
Research and publications are maintained in `research.md` and `publications.md`.
The CV link points to `RichterCV.pdf`.

## Add an announcement

Create a Markdown file in `_news/` with front matter at the very first line.
Use a stable descriptive filename, optionally prefixed by the known year/month.

```markdown
---
layout: news
title: "Your announcement title"
event_date: "2026-10"
featured: false
---

A short first paragraph appears as the announcement excerpt.

Additional details, Markdown links, and images go here.
```

Use a quoted ISO `event_date` at the precision supported by your sources:
`"2026"` (year), `"2026-10"` (month), or `"2026-10-14"` (verified day).
Do not add a Jekyll `date` field with an invented day. The shared includes sort
by `event_date` and show only its known precision, including in HTML time elements.
Year-only entries sort after the dated entries in their year. Entries with the
same date have no implied order within that period.

Set `featured: true` to include an entry in the subtle announcement panel near
the top of the homepage (the two newest featured entries). For initiatives,
optionally add `initiative_url` and `initiative_link_text` to show an official
website link in both the panel and the announcement page. The homepage news
list shows the first paragraph of ordinary entries as a short announcement.
Featured entries show only their title there, so their description is not repeated.
Write entries as brief updates (for example, “I will serve on the research-track
program committee for ASE 2026”), rather than as a CV summary. Keep separate
service appointments in separate files. Do not infer an appointment month from
the conference dates; use year-only precision until the month is confirmed.
The five newest entries appear in recent news; all entries appear at `/news/`.
Each entry gets its own page automatically. No plugin or layout changes are
needed. An optional `sources` list records verification references for editors.

The filename determines the default URL, independently of `event_date`.
If renaming an existing entry, set `permalink` to its original URL to preserve
links; the Clarification Challenge retains its original URL for this reason.
Future entries are hidden from the homepage and archive until a build on or
after their `event_date`. Collection pages may still be generated by Jekyll;
keep unpublished drafts outside `_news/` if they must not have a public URL.

For internal links and images, use the `relative_url` filter, for example:
`[Research]({{ '/research/' | relative_url }})`.

## Update publications

Publication entries live in `_data/publications.yml`, with authors in publication
order, a year, venue, and canonical paper URL. Set `status` to `published`,
`preprint`, or `thesis`; entries are grouped by year automatically. Keep published
papers and their author versions in one entry, using the optional `preprint`
field. Optional `pdf`, `code`, and `artifact` fields add resource links.

Use a unique, stable `id` for each entry. Research links point to these IDs on
the publications page. The `sources` field records bibliographic verification
references for editors. Add accepted or published venues only when verified;
otherwise keep manuscripts in the preprint section.

## Build locally

The Gemfile uses `github-pages` to match GitHub Pages’ supported dependency set:

```sh
bundle install
bundle exec jekyll build --safe
bundle exec jekyll serve --safe
```

Use a Ruby version compatible with the GitHub Pages dependency set. Local Ruby
compatibility shims, lockfiles, and generated output are not site source and
must not be committed. Safe mode disables local plugins, matching GitHub Pages.

`url` is the production origin and `baseurl` is empty for this user site.
For a repository project site, set `baseurl: "/repository-name"`; templates and
Markdown links use `relative_url` so navigation and assets follow that prefix.
